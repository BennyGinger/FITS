Tracking post-processing for static cells
-----------------------------------------
[x] Implemented a FITS-owned, tracker-agnostic static-mask postprocessor.
    It restores stable identities with a temporal nonzero-mode super-mask,
    removes masks that differ from each track's consensus shape, discards
    tracks below the minimum-appearances threshold, fills internal gaps, and
    optionally extrapolates the first and last valid masks to the sequence
    boundaries. Existing valid masks are protected and conflicting generated
    masks fall back to the disjoint super-mask shape to avoid halo artefacts.
    Settings are integrated into the tracking task, TOML configuration, and
    the GUI's basic settings. The implementation remains independent of
    `tracklink`, allowing future tracking backends to reuse it unchanged.


Manual tracking viewer/editor
-----------------------------
[x] Build a dedicated FITS tracking viewer/editor, reusing the existing image
    viewer's navigation and interaction patterns but with a multi-label
    track overlay and track-aware session/model (not the binary mask canvas).
[ ] Support point-track annotation as explicit `(frame, x, y, track ID)`
    observations. Treat a click as a seed meaning "this is my cell", not as
    its final centroid. Use the seed to propose a mask only after an explicit
    segmentation action; after the user accepts or edits that mask, calculate
    its centroid and use only that recalculated centroid for the displayed
    track path.
[ ] Add click-seeded, local cell segmentation for manual tracking and for
    creating tracks from scratch when no `fits_track.tif` exists. The first
    implementation should target isolated, irregular neutrophils and
    macrophages on a relatively dark background and must not assume roundness
    or temporal shape stability.

    Plan of action:
    1. Let the user choose an approximate overall cell size. Use it to define
       and, when necessary, expand the local search region around the click;
       do not use it as a circular shape constraint.
    2. Build a fast default proposal from the current raw-image plane using
       local background estimation, gentle denoising, foreground thresholding,
       and the connected foreground region containing the clicked seed.
    3. Add a seeded watershed option for a bright region containing multiple
       cells. Each positive click identifies one cell; optional negative or
       background clicks constrain leakage into neighbours or hotspots.
    4. Evaluate seeded random walker or a local active-contour refinement for
       uneven cell intensity, faint protrusions, and incomplete boundaries.
       Keep these as alternative proposal backends rather than mandatory
       dependencies. Consider prompt-based Micro-SAM later if classical local
       methods are insufficient on representative data.
    5. Show every generated boundary as a proposal before committing it. Reuse
       the mask editor's add/erase tools so the user can correct protrusions,
       holes, leakage, or missed regions manually, then accept or cancel it.
    6. On acceptance, store the mask with its track ID and recalculate the
       centroid from the final edited mask. Preserve the original click in the
       correction log for audit/debugging, but do not display a second path.
    7. For a gap with valid masks before and after it, offer mask interpolation
       and image-refined interpolation as explicit alternatives. Because these
       immune cells can change shape sharply, never apply interpolation without
       preview and user acceptance.
    8. Support a new-session mode opened from `fits_array.tif` without a
       tracking artifact. Starting a track allocates an ID; accepted seeded
       masks add detections to it. Adapt the saving panel to create a new
       `fits_track.tif` as well as save corrected copies of existing tracking
       artifacts.
    9. Add undo/redo for seed placement, mask proposals, manual mask edits, and
       track assignment. Record the proposal method, its settings, the seed,
       the accepted centroid, and subsequent edits in the correction log.

    Validation is deferred until representative neutrophil/macrophage movies
    are available. Compare methods on isolated cells, large shape changes,
    faint extensions, touching cells, and bright multi-cell hotspots before
    selecting defaults.
[ ] Load an existing tracked-label movie for manual correction: inspect a
    selected object across time; split a track at a frame; merge/reassign
    tracks from a chosen frame onward; remove detections or tracks; and
    provide undo/redo plus unsaved-change protection.
[ ] Save the finalized corrected label movie as the tracking artifact and
    record manual edits/provenance in a compact correction log so the result
    remains auditable and can later support replaying edits.

Optional processing tuners
-------------------------
Goal: let users quickly check representative experiments and choose settings
before running a batch, minimizing hands-on time. Early previews on the
original input are acceptable approximations of the final pipeline result;
do not require users to run preceding steps before tuning.
Status: proposed design; implementation pending.

User interface and launch
[ ] Provide distinct time-registration, channel-registration, and background-
    subtraction tuners, launched explicitly from their respective GUI sections.
    Each should look and behave as its own tool, rather than requiring users
    to navigate a combined processing workflow.
[ ] Offer manual standalone CLI launch commands for each tuner (names TBD).
    Keep the normal pipeline CLI fully usable without opening any tuner.
[ ] Reuse the run-directory browser to choose a representative experiment.
[ ] Provide original/preview comparison, frame navigation, relevant settings,
    Preview, and Apply and close. Applying transfers settings to the matching
    main-GUI section; closing without applying leaves those settings unchanged.
[ ] Keep previews optional and separate from saved experiment artifacts.
[ ] Consider separate executable shortcuts/icons for the tools later.

Input and preview lifetime
[ ] Load one original input array for the active tool; do not load duplicate
    full stacks for inactive tools. Resolve support for raw files versus
    converted, unprocessed FITS arrays when implementing the input loader.
[ ] When switching tools, release the previous tool's input and preview,
    then reload the selected experiment for the newly opened tool.
[ ] When switching experiments, release the previous input and preview before
    loading the new experiment. Do not accumulate results across experiments.
[ ] Reuse the loaded original input for repeated previews within a tool.
    Replace the previous preview; never process the previous preview again.
[ ] Run preview work off the GUI thread with progress and cancellation.
    Finish or cancel active work before releasing its input buffers.

Preview scope
[x] Initialize and cache SegTune's selected Cellpose model in the background
    without running an automatic preview. Keep tuning controls editable while
    loading, disable Run preview until ready, and initialize the latest model
    selection when it changes during an existing load.
[ ] Channel registration: preview one time frame at a time using a composite
    display with channel colours, visibility controls, and original/result
    comparison. Build the composite only for the displayed frame.
[ ] Time registration with previous-frame reference: process the full sequence
    for a faithful preview of accumulated transforms.
[ ] Time registration with first-frame reference: preview individual frames
    against the fixed first frame.
[ ] Time registration with mean reference: compute and reuse the full-stack
    mean reference, then preview individual frames against it. Computing the
    reference still requires reading the stack.
[ ] Background subtraction: preview individual frames/channels directly from
    the original input, without requiring registration first.
[ ] Follow the same early-check principle for segmentation tuning; preceding
    processing steps are not a prerequisite for optional tuning.
[ ] Document that early previews guide parameter choice rather than reproduce
